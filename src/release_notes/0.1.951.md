The editor's vertical scrollbar becomes an overview ruler, the whole-file
summary VS Code and Zed paint down the same track. A compile error two hundred
lines below the fold, or the other eleven hits for what you just searched for,
are now visible without scrolling to find out they exist.

Each tick is one `━` in the colour of the decoration it stands for: red and
amber for errors and warnings, orange for a search match, and the git gutter's
own green, blue and red for added, modified and deleted lines. Ticks are drawn
as a foreground glyph over the track, so the thumb still shows through
underneath and you do not lose sight of where you are in the file.

A terminal gives the ruler one column where VS Code has three lanes, so when
several lines compress onto one track row only the most urgent mark is shown.
The order is fixed and tested: an error beats a warning, a warning beats a
search hit, and any of those beats a git change. A broken build is never
hidden behind a whitespace edit.

Search ticks are computed by asking the same function the search highlighter
asks, with the same case-sensitivity and regex options, so the ruler and the
highlighted runs in the text can never disagree about what matched.

`View: Toggle Overview Ruler` in the command palette turns it off for a plain
scrollbar.
